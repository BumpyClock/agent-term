# Base Windows Terminal parity

This baseline covers local interactive shells, tabs and panes, terminal rendering, selection and clipboard commands, scrollback, history search, zoom, and solid/acrylic appearance. It does not claim complete Windows Terminal compatibility.

| Area | Implementation | Verification |
| --- | --- | --- |
| ConPTY shells | Independent PowerShell and Command Prompt sessions; installed WSL distribution profiles; normal PowerShell profile loading | Native shell tests pass for launch, independent state, interrupts, resize, output draining and cleanup. WSL discovery and argument quoting pass; distro shell execution remains untested. |
| Tabs and panes | Profile menu, tab switching, nested splits, directional focus, mouse/keyboard resizing, close active pane/tab, await-all window shutdown | Live checks confirm tab creation, retained output after switching, full-height layout, both divider orientations, keyboard resizing, and nested collapse retaining the original session. |
| Rendering | ANSI/indexed/RGB colors, Unicode cells, styles, cursor shapes, alternate screen; theme-aware default text, cursor and ANSI palette | Native and Win2D pixel tests pass; full-screen console fixture passes. Windows and Boat theme checks cover live changes, preserved content/history/selection, application RGB/OSC overrides, and color-scheme queries. Light single and split panes were visually checked. |
| Application mouse | Native mouse-mode encoding for buttons, releases, motion, wheel, and SGR pixels; Shift local override; Ctrl-wheel zoom | Windows and Boat protocol checks pass for tracking modes, coordinates, modifiers, resize and DPI. A real ConPTY fixture verifies press/release/wheel, Shift bypass, and tracking disable. Full mouse-enabled TUI interaction through the WinUI surface remains unverified. |
| IME input | Native WinUI input host at the terminal cursor, local preedit, commit-only forwarding, composition-aware shortcuts and cursor ownership | Windows and Boat tests pass for text routing and composition state; renderer pixels cover suppression of the terminal cursor. Live ordinary text, Unicode, physical key input, and mouse selection starting inside the input host pass. Real IME composition and candidate placement remain unverified. The machine has only US English input, and the user requested no language-configuration changes. |
| Scrollback | Wheel, scrollbar and keyboard navigation; retained history after stop/exit; input snaps to bottom | Native and real shell tests pass. Live wheel navigation reveals older lines; Ctrl+Shift+End returns to the latest output. |
| Selection and clipboard | Linear, word, line, rectangular and extended selection; autoscroll; native text formatting; paste framing; viewport pinning during output | Native and pixel tests pass. Live drag, Ctrl+C/Ctrl+Shift+C copy, Ctrl+V/Shift+Insert/right-click paste, and selection retention during output pass. |
| Search | Previous/next history matches with wrap and exact-case option | Native search tests and live match/no-match checks pass. Case-insensitive matching folds ASCII only. |
| Zoom and settings | Per-pane zoom; shared appearance defaults with independent per-shell font family/size and solid/acrylic overrides | Windows and Boat tests cover inheritance, persistence, explicit Automatic/Solid values, legacy settings, and unavailable profiles. Live checks confirm independent appearance updates in PowerShell and Command Prompt panes. |

## Known gaps

Live IME composition/candidate validation, a terminal UI Automation text provider, keyboard selection/mark mode, custom key bindings, advanced profile editing, extension APIs, and complete VT compatibility testing remain outstanding. Window/session layout restoration is not yet implemented.

Native tab reordering passed a user-performed held drag. Command Prompt moved before PowerShell; UI order and a temporary native event trace confirmed `Move` with both tab identities retained. The available automation released after about 22 ms and returned `None`, so its instant drag is inconclusive. See [interaction testing](interaction-testing.md) for the repeatable manual check and automation limitation.

Resize now publishes the resized terminal frame immediately for running and stopped sessions. Refresh timers remain active across transient pane reparenting; tab visibility and session teardown own their lifetime. Native width-only resize checks pass without focus or input. Live splitting and divider widening/narrowing confirmed that an unfocused pane reflows immediately without clicking into it.

The next core priorities are live validation of IME text entry and candidate positioning, accessible terminal text, then keyboard mark mode and configurable actions. These affect input and access before broader profile and session-management features.

Switching primary/alternate screens clears selection. Acrylic currently identifies default backgrounds by resolved RGB, so an explicit ANSI background with the same RGB is transparent too. Settings offers installed terminal fonts; automatic selection prefers an installed CaskaydiaCove Nerd Font before Cascadia Mono and Consolas.

The card layout follows the user's later pane reference. The main and Settings windows use Mica and Windows caption controls. Acrylic panes use independent `SystemBackdropElement` targets with a host-backdrop effect using the terminal's actual background color and automatic tint/luminosity calculations. A `DesktopAcrylicController` policy target supplies native fallback and high-contrast brushes. The active pane effect omits the UWP recipe's 2% grain texture. Solid mode and 100% opacity clear the brush while retaining the native target. Windows controls inactive-window and accessibility fallbacks. Window and element backdrops can coexist under the [WinUI system backdrop model](https://learn.microsoft.com/en-us/windows/apps/develop/ui/system-backdrops).

The SDK 2.6.5 preview visibly samples desktop content inside acrylic panes. A live split trace reproduced a late `Unloaded` event detaching the still-visible original pane's settings subscription. Subscriptions now follow explicit pane disposal. Resumed live checks confirmed both the original and newly split pane respond to saved 0%, 85%, and 100% values without reopening. Windows Terminal's `TermControl::_CreateAcrylicBrush` uses its terminal background, tint opacity, and automatic UWP brush luminosity. A nonvisual controller probe showed fixed luminosity opacity even when tint opacity changed. AgentTerm now computes separate active tint and luminosity colors instead. Equal percentage values are not yet verified to produce identical pixels.

The revised acrylic Release build and renderer checks pass. Regression checks cover black, near-black, light and saturated backgrounds, byte rounding, blend semantics, distinct rendered output at 0/50/85%, and a solid result at 100%. A separate nonvisual composition probe instantiated the production effect on the native controller's compositor and read back changing tint and luminosity properties. These checks establish the effect calculation and composition support, not live split-pane attachment, focus transitions, or visual parity with Windows Terminal.

The main window explicitly enables `DWMWA_USE_HOSTBACKDROPBRUSH`, the [documented Win32 opt-in for custom host brushes](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute). This enables desktop sampling for the pane effects while the window's own `SystemBackdrop` remains Mica.

The host graph preserves the upstream compositor's blend-mode ordering. Offscreen Win2D checks establish opacity responsiveness and color arithmetic, not identical Windows compositor pixels. A further constructor-order probe found that setting only the native controller's fallback color left its transition tint white, even with a dark configuration. Both native tint and fallback now track the terminal background. The supplied 1.9-second recording contained no measured full-pane white spike in its 57 frames. The user clarified that the whole pane flashed, rebuilt the app after the transition-tint fix, and reported that it appeared fixed. This is a user-reported manual result, not an automated focus-transition check or proof of the recording's cause.

Resumed focus checks captured the active gray acrylic surface and inactive black fallback without a white frame. These discrete captures cannot exclude a brief flash. Changing split panes across 100% opacity and closing the last tab exposed three native crashes. Dump analysis found finalizer-thread WinRT releases, `RPC_E_WRONG_THREAD` while closing a content site, and repeated `ContentExternalBackdropLink` disposal symbols in native stack slots. The fix keeps each backdrop assigned throughout the pane's lifetime and retains the borrowed target until WinUI disconnects it. Pane disposal releases only owned controller/effect resources on the UI thread. This follows the [PowerToys backdrop ownership pattern](https://github.com/microsoft/PowerToys/blob/main/src/modules/cmdpal/Microsoft.CmdPal.UI/Controls/TintedBackdrops.cs). Independent source review and an isolated Release build passed with zero warnings/errors. Escape stopped automation before the corrected build's live stress check. Crash-free material changes and shutdown remain unverified. Original preferences were restored with matching SHA-256 hashes.

Live checks observed intermediate entrance and exit frames, completed pane removal, and repeated split/close without stranded panes. Closing the window immediately after closing a pane exited the app and all six observed shell/conhost child processes. The reduced-motion branch was reviewed but not runtime-tested; no Windows animation setting was changed.

## Comparison evidence

The user's Windows Terminal screenshots establish the compact tab-strip layout, profile dropdown, acrylic appearance, and normal PowerShell prompt behavior. Computer Use explicitly blocked Windows Terminal itself; its live behavior was not automated. AgentTerm's UI has been exercised directly for the flows listed above.

At 85%, the current active AgentTerm capture's lower-center blank region has mean weighted RGB brightness 31.23/255, compared with 33.06/255 in the supplied Windows Terminal reference and 5.10/255 in the earlier near-black AgentTerm screenshot. The calculation uses `0.2126 R + 0.7152 G + 0.0722 B` on encoded RGB values, not physical luminance. Different window sizes, underlying scenes, and capture times prevent a pixel-parity conclusion. Windows Terminal's missing-in-AgentTerm 2% grain is another known difference. The product's automation policy blocked a new controlled Windows Terminal capture.

Live clipboard checks compared copied text with the exact selected text and pasted distinct commands through each tested shortcut. Ctrl+C without selection interrupted a 30-second sleep. A selected history region remained at the same viewport offset through 20 timed output lines and remained copyable afterward. Solid/acrylic changes and per-pane zoom were visually verified. These checks supplement automated native, ConPTY, and rendered-pixel tests.

Settings opens in a separate window with Startup, Profile defaults, and each shell's Appearance page. Live checks confirmed terminal input while Settings was open, unchanged window bounds during page changes and validation errors, cross-page draft validation, Save without closing, Discard, unsaved draft removal on close, reuse after minimization, and settings-window cleanup when its terminal window closes.

Per-profile live checks confirmed that Command Prompt overrides update existing and newly split Command Prompt panes while PowerShell panes remain unchanged. Saving an unrelated profile preserved a zoomed PowerShell pane. Changing Defaults updated inheriting panes while keeping explicit overrides; Reset restored inheritance for both panes of the same profile. The original settings file was restored and its hash checked after testing.

A Command Prompt font-family override changed its live pane without changing the adjacent PowerShell font. Saving an invalid profile draft from another profile now navigates to the invalid field and keeps the error visible on the first Save. Independent 6.1-terra-high UX review accepted the main and minimum-width settings layouts and prompted full font-value tooltips and visible inherited values.

The chrome refinement keeps 4-DIP gutters and native shadows with quieter pane actions and rounded pill tabs. A later visibility refinement adds a faint one-DIP boundary to every pane, light in dark mode and dark in light mode, with a system-color high-contrast fallback. The dark pane boundary was visually checked in the tab and acrylic previews; its final light-mode check remains pending. Live checks confirmed hover emphasis, keyboard focus and activation, and profile opacity Save/Discard/inheritance. Solid mode disables the opacity slider. Original preferences were restored and their hash verified. Independent 6.1-terra-high visual review found no blocker in the supplied light/dark captures. An independent 6.1-sol-high judge rated the implemented chrome/settings/theme visuals 9.1/10. This is a subjective screenshot assessment, not a claim of full terminal parity or accessibility conformance.
