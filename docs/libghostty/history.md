# Search, prompt navigation, and rich history

Open Find with Ctrl+Shift+F. Search covers retained primary/alternate screen history. Enter moves toward newer matches. Shift+Enter moves toward older matches. Navigation wraps. The status reports total matches. Native matching ignores ASCII letter case only. Match case filters candidates using ordinal selected text. There is no native case-sensitive option. Case-sensitive totals appear after filtering completes.

The find bar History menu has previous/next prompt, copy formatted selection, and HTML/styled VT save actions for history or selection. Ctrl+Alt+Shift+Up and Ctrl+Alt+Shift+Down navigate semantic shell prompts. These shortcuts do not replace the existing Ctrl+Shift history scrolling shortcuts. Shell OSC 133 semantic markers are required. Navigation uses delta_prompt, including after reflow, and does not replace tracked agent task anchors.

Exports use the native formatter, separate from live rendering and command transcript capture. History means the complete current screen including retained scrollback. Selection means the inclusive native selection, including rectangular semantics. Missing selection performs no copy/save. Exports unwrap soft wraps and trim trailing whitespace. Public GhosttyTerminal.ExportHistory allows both policies to be changed. HTML contains native style/palette markup and escaped content; Unicode may use numeric character references. Styled VT contains terminal control sequences and should be treated as terminal output when replayed. Clipboard copy includes HTML plus plain text. File save takes an owned snapshot before opening the picker, so later output does not change the saved text. Save cancellation creates no file.

TerminalSession.FindAsync owns one native search via a semaphore. Each feed and tick holds _gate for that native step, then releases it before reporting progress or yielding. Query replacement, synchronous Find, and disposal exclude ticks through that semaphore. The app cancels obsolete queries and ignores stale progress. Output/resize revisions cause re-feeds before another tick; results are not published across a revision change. Selection and viewport changes take _renderGate then _gate. Exact-case filtering and match navigation release locks between candidates. Synchronous Find remains for compatibility and direct single-threaded tests; the find UI never calls it. Hiding/unloading the pane cancels interactive work. No idle find polling is scheduled.

Idle compression observes compression_activity after output/reflow and history access. A changed token schedules a two-second one-shot delay. Incremental callbacks serialize through _renderGate then _gate. Pending steps schedule one continuation after 25 ms; complete/unsupported results schedule nothing. Output restarts the idle delay and disposal stops the timer. Native compression preserves logical contents and tracked references. Memory accounting belongs to the host geometry/diagnostics feature; this module exposes the activity token and bounded compression step without duplicating diagnostics.

Contracts were checked against the pinned native search.h, formatter.h, terminal.h, and point.h. Both the 1.0.0 source and downloaded 1.0.1 archive read `history.start_pin.node` in `src/terminal/search/screen.zig` inside `tickHistory`, despite the header's independent-tick contract. Integration therefore serializes each tick with terminal mutations. This preserves incremental cancellation and progress without relying on native race freedom. A tick consumes the currently loaded search window, so its duration depends on that window and match density; it is not a hard real-time bound.

Focused verification commands are `dotnet run --project tests/AgentTerm.Terminal.Smoke -- --history-features-only` and `dotnet run --project tests/AgentTerm.ConPty.Smoke -- --history-search-only`. The parent runs aggregate Windows/Boat verification and visual interaction checks sequentially.
